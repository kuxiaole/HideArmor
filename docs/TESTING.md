# 验证记录

验证日期：2026-10-29（Asia/Shanghai）。

## 环境

- Windows 11，Zulu JDK 25.0.3，Gradle 9.4.1。
- 官方 Folia `26.3-5-ver/26.3.x@8cffa90`，API `26.3.build.5-alpha`。
- 官方 `packetevents-spigot-2.14.0.jar`。
- 隔离测试服仅监听 `127.0.0.1:25587`，使用由 26.2 测试服复制后升级的测试世界。
- 联调客户端是无画面的 26.3 协议客户端，不是真人游戏客户端。

## 自动测试：21 项通过

执行 `gradlew clean build`。测试运行时固定为 PacketEvents `ServerVersion.V_26_3`，使用真实 PacketEvents 26.3 物品映射和编解码器。

- 五个独立开关，包括铜盔甲、海龟壳和鞘翅分类；一键全部隐藏、显示。
- 保留原物品类型、数量、耐久、自定义名称、滑翔组件和所有原始组件补丁。
- 不修改 PacketEvents 共享的默认装备组件，只对副本创建新的可穿戴组件。
- 头颅、南瓜、武器和空物品不受影响；观察者手持装备不被隐藏。
- 头盔保留非空外观标识，并保留穿戴、换装、剪切等组件字段。
- 创造模式回传恢复原始自定义装备外观；未知连接、错误物品类型、组件篡改和缓存淘汰均拒绝恢复。
- 缓存上限 256；四个线程执行 800 次投影和还原，未修改原物品或产生额外缓存项。
- 七种背包点击类型保留原动作、窗口、槽位和按钮，清除不可信预测并请求服务端完整同步。
- 窗口物品、单槽位、玩家背包、光标、创造模式物品和实体装备包完成 26.3 二进制编解码往返。

## Folia 26.3 实际联调

官方 Folia JAR 的 SHA-256 为 `c105f6be9463b2da37568b620e81b9ab2f6a6ae771f8fff9caf7a1c0946b340a`。服务端两次正常启动，识别 API `26.3.build.5-alpha`，PacketEvents 加载 `V_26_3/23` 映射，HideArmor 1.1.0 正常启用和停用。

| 场景 | 实际结果 |
| --- | --- |
| 普通玩家执行 `/ha` | 收到中文无权限提示，不打开菜单 |
| OP 执行 `/ha` | 打开标题为“盔甲隐藏控制”的 27 格菜单 |
| 点击头盔开关 | 本人头盔物品收到临时隐藏外观，其他装备未变化 |
| 点击“一键隐藏” | 本人头盔、护腿、靴子和鞘翅均收到隐藏外观 |
| 退出、正常停服、重启并重新登录 | 一键隐藏选择保留，四个已装备物品重新收到隐藏外观 |
| 正常停服 | HideArmor 和 PacketEvents 正常停用，未见 HideArmor 堆栈或线程所有权异常 |

Windows 性能计数器探测仍会产生 OSHI 警告，与插件无关。26.3 测试客户端尚未正确处理新版登录后位置确认，服务端会记录该测试客户端的 `moved too quickly` 警告；因此这次没有用该客户端确认观察者视角、跨区域移动、重生或创造模式回传。上述项目在 26.2 上曾通过，但不能据此标记 26.3 已通过。

## 仍需原版 26.3 客户端验收

1. 使用两个无模组的原版 Java 版 26.3 客户端检查第三人称、背包人物预览、他人视角和物品图标，覆盖皮革染色、附魔光效和盔甲纹饰。
2. 依次操作五项开关和一键按钮，测试穿脱、Shift 快速装备、数字键交换、拖拽、丢弃和拾取。
3. 在菜单尝试 Shift 点击、数字键、双击收集、拖拽和丢弃，确认不能取出菜单物品。
4. 验证隐藏时的防御、附魔、耐久消耗和鞘翅起飞、滑翔。
5. 验证关闭 `keep_inventory` 时的死亡掉落、下界和末地换世界、两位玩家同时快速操作、重新进入视距及跨区域移动。
6. 验证创造模式复制、未知投影回传拒绝，以及目标权限插件的实时授权和撤权。

上述 26.3 视觉、观察者、飞行、跨区域和完整多人压力场景没有标记为已通过。
