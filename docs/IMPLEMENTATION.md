# 实现边界与线程检查

目标仅为 Folia 26.3，使用 folia-plugin-dev 规则 9：直接调用官方实体调度器，不增加 Bukkit 调度兼容层。

| 入口和调用链 | 当前上下文 / 数据所有者 | 跨线程数据 | 清理与约束 |
| --- | --- | --- | --- |
| 上线 → 读取 PDC → 建立会话 | 玩家所属区域 / 玩家 | UUID、权限和隐藏位掩码 | 下线移除会话，规则 2、6、8 |
| 命令、菜单点击 → 修改选择 → 刷新 | 玩家实体调度器 / 玩家及其背包 | 独立的数据包物品快照 | 菜单点击取消物品移动，规则 6、7、8 |
| 每 20 tick 权限检查 → 刷新外观 | 玩家实体调度器 / 玩家 | volatile 位掩码 | 下线、实体退休、停用取消，规则 6、7、8 |
| PacketEvents 发包 → 替换展示组件 | 网络回调 / 当前数据包 | 会话并发索引、独立物品组件 | 不访问 Bukkit 实体或背包；规则 2、6 |
| 创造模式回传 → 还原展示组件 | 网络回调 / 当前数据包 | 有上限的可信展示映射 | 无法还原则取消并请求实体线程同步；规则 2、6、8 |
| 停用 | 服务端停用上下文 | 已缓存数据包快照 | 停止监听、取消任务、清空引用；不跨区域读取背包 |

## 已发现的限制

- `must_fix`：PacketEvents 2.14.0 的 `HashedStack.fromItemStack` 对新增组件使用占位哈希 0，不能用于还原真实点击预测。实现改为保留点击动作，丢弃客户端预测并令服务端完整同步，不伪造组件哈希。
- `must_fix`：`ItemStack.copy()` 只复制组件映射；被修改的 `ItemEquippable` 必须单独新建，不能修改共享的默认组件。
- `uncertain`：双客户端画面、真实 Folia 多区域运行只能通过实际游戏测试确认，静态检查与单元测试不能代替。

## 实现后的三轮复核

1. 功能与范围：五项开关、中文菜单、命令、OP 默认权限和 PDC 保存已接通；真实装备不调用任何写入 API。
2. Folia 与性能：仅使用官方实体调度器，周期任务为 20 tick；数据包回调不访问 Bukkit 玩家/背包。只在主动刷新时扫描观察者，不做每 tick 全服装备广播。
3. 生命周期：下线、实体退休、停用均清理会话、任务与缓存；会话索引使用并发映射，外观恢复缓存以短临界区保护并限制容量。数据包还校验连接身份，避免旧连接覆盖同 UUID 的新会话。

26.3 的 PacketEvents 组件与真实编解码器确认 `equippable.asset_id`、实体装备、玩家背包、窗口、光标、点击预测和创造模式物品包仍可按当前实现往返。点击 state ID 不匹配时由服务端发送完整权威状态。实现没有依赖技能中列为不可用的重生、传送或换世界事件；通过数据包和玩家实体任务恢复同步。

真实 Folia 26.3 启动、菜单、本人隐藏和重启保存已进行协议客户端联调，详见 `TESTING.md`；观察者、跨区域、重生和真人画面仍需在 26.3 复测。

源码核验材料和隔离测试服存于忽略的 `.local/`。
