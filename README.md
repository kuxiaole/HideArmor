# HideArmor · Folia 26.3 隐藏盔甲

玩家可分别隐藏头盔、胸甲、护腿、靴子和鞘翅，也可一键隐藏或显示。提供中文箱子菜单。隐藏时保留真实装备、背包图标和装备属性。

## 安装

1. 使用 **Java 25** 和 **Folia 26.3**。编译与本地启动验证使用 `26.3-5`（API `26.3.build.5-alpha`）。Folia 26.3 当前仍为 Alpha。
2. 安装官方 [PacketEvents 2.14.0](https://github.com/retrooper/packetevents/releases/tag/v2.14.0) 发布页里的 **`packetevents-spigot-2.14.0.jar`**。
3. 将 `build/libs/HideArmor-1.1.0.jar` 与上述前置一起放进服务器 `plugins/`。
4. 正常重启服务器。玩家输入 **`/hidearmor`** 或 **`/ha`** 打开菜单。

插件严格检查 PacketEvents 2.14.0 和 Minecraft 26.3，版本不符合时停止启用。不要用代理端的 PacketEvents JAR 替代 Spigot 版。

## 权限

| 权限 | 默认 | 用途 |
| --- | --- | --- |
| `hidearmor.use` | OP | 打开菜单并控制自己的隐藏部位 |

普通玩家默认没有权限，OP 默认可以使用。通过服务器的权限插件授予 `hidearmor.use` 即可开放给玩家。插件本身不要求特定的权限管理插件。

权限每 20 tick 检查一次；撤权后关闭菜单、恢复显示，保存的选择仍保留。重新授权后自动应用之前的选择。服务器卡顿时，20 tick 可能超过一秒。

## 使用说明

- 菜单中间为头盔、胸甲、护腿、靴子、鞘翅五个按钮，左键或右键切换，文字显示当前状态。
- “一键隐藏”和“一键显示”覆盖全部五项。鞘翅与胸甲独立，切换穿着的物品时应用对应开关。
- 自己的第三人称、背包人物预览与其他玩家视角均使用隐藏外观；物品栏中的图标仍然正常。
- 新玩家默认全部显示。选择保存在玩家 PDC 的 `hidearmor:hidden_parts` 中，随玩家存档保存，无需数据库或独立配置文件。
- 头颅、南瓜、手持物品和其他实体的装备不在隐藏范围内。
- 装备耐久、属性、附魔和鞘翅飞行由服务端真实物品决定，插件不修改这些物品。

## 构建

安装 JDK 25，并让 `JAVA_HOME` 指向该目录。

Windows PowerShell：

```powershell
.\gradlew.bat clean build
```

Linux / macOS：

```sh
sh gradlew clean build
```

输出：

- `build/libs/HideArmor-1.1.0.jar`：服务器插件，不包含前置或测试库。
- `build/distributions/HideArmor-1.1.0-source.zip`：完整插件源码、Gradle Wrapper、测试和文档。
- `build/reports/tests/test/index.html`：自动测试报告。

Gradle Wrapper 固定为 9.4.1，第一次构建需要联网下载依赖。源码与资源使用 UTF-8；Gradle 启动参数兼容 Windows 中文目录。

## 实现与已知边界

- 其他玩家的装备包只隐藏选定槽位；本人收到的背包物品副本仅替换 `equippable.asset_id`，无需资源包或客户端模组。
- 为保证客户端预测穿脱时仍保持外观一致，玩家收到的背包、容器和光标中的同类装备也使用临时外观组件；物品图标和服务端物品不变。
- PacketEvents 2.14.0 无法计算完整的 Minecraft 组件哈希。因此使用过隐藏的连接，在背包点击后由服务端完整同步物品状态，直到玩家下线。点击动作仍由原版服务端执行，代价是这些点击会发送更多背包数据。
- 创造模式回传的临时组件只按当前连接的可信映射恢复；未知、过期或被篡改的映射会被拒绝并重新同步。每个玩家最多缓存 256 种装备外观组件。不要把隐藏状态下的物品存入客户端“已保存的快捷栏”跨登录使用；先显示装备再保存。
- 加载和跨区域调度至少需要一个 tick。首次进入服务器时，初始背包同步后会补发隐藏状态。
- 安装、更新、移除插件请正常停服再操作；不支持在线热卸载。跨版本客户端、基岩版、修改装备渲染的客户端模组，以及其他同时改写装备数据包的插件未做兼容保证。

## 验证情况

已通过编译和 21 项自动测试，并在本机 Folia 26.3-5 + PacketEvents 2.14.0 上完成插件加载、权限、菜单、单项隐藏、一键隐藏和重启保存联调。26.3 协议测试客户端的移动确认流程尚未更新，因此本次没有把观察者视角、跨区域、死亡重生和创造模式联调标记为通过。

**尚未完成真人原版 26.3 客户端的画面验收。** 协议联调不能替代第三人称、人物预览、纹饰、附魔光效和实际飞行的肉眼检查。详细结果与复测步骤见 [docs/TESTING.md](docs/TESTING.md)。
